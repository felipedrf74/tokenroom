## Menu bar

Enabled + connected providers only:

```
  Percents:  [glyph] 2%   [glyph] 9%   [glyph] 32%
  Meters:    [glyph]|     [glyph]|     [glyph]|
```

`AppSettings.menuStyle` is Percents or Meters. The percent or meter is the open window that needs attention soonest (a reached limit, then the tightest run-out, then the most used), not always the weekly headline. When that window is not the primary one, the tooltip and accessibility label name it ("5-hour 55%") and name the primary window beside it ("Weekly 10%"). The drawn extra stays one figure wide. Meters are vertical rounded rectangles: 8.05×18pt, 1.6pt corners (soft, not a pill), 1pt primary outline. Used fill sits in an inner well 1.2pt off the stroke so it does not touch the outline. Fill height is `wellHeight × usedPercent / 100` from the bottom of that well. Glyphs are 17.22pt. Grok and GPT marks are vector templates (full even-odd Grok slash, not a cropped PNG). Menu-bar fill is one color by used % (light blue / yellow / orange / red). Popover meters keep the light-blue → red gradient. No leading health dot. Provider icons show in the popover and Settings via `ProviderIcon`, which is the shared `ProviderMark`. Short names: Build, Bot, Claude, GPT, Cursor. Loading, and rate limited before a first reading, use `–%`. Percents are whole numbers (`55%`, not `55.2%`). Signed-out / expired providers are omitted. Never hide an enabled connected provider. Opening the popover refreshes if the last attempt is older than 45s. Unchanged usage does not rewrite status or the menu extra. Highest keeps the provider whose shown window is most urgent, then the most used.

The extra is an **AppKit `NSStatusItem`** hosting `MenuBarLabel` in a passthrough `NSHostingView`. Click opens an `NSPopover`. Settings is `AppDelegate.openSettings`. `LSUIElement`. Install to `/Applications/Tokenroom.app`.

## Providers

Protocol `ProviderClient.fetch() async -> Result<QuotaSnapshot, ProviderError>`, with an optional `fetchBudget` (20 s default). Parallel refresh. One failure never blocks the others. Credentials are read in place. Grok Build and Codex access tokens are renewed in that tool's own login about three minutes before they expire, and the new access and refresh tokens are written back; they are not kept after that write, and nothing from a login is logged. Claude's access token is renewed in place about three minutes before it expires, and the new login is written back with the `security` tool. Every other provider is read only. The cache holds percentages, reset times, window and plan names, and amounts (balance, spend, credits); never identities. `Provider.descriptor` is the one catalog entry per provider; `access` says whether it connects with a local login, a coding-plan key (pasted, or found in another tool's config on the Mac), or a pasted key. Windows are ordered primary first.

Timeout 12s per request, 20s per provider (35s for Antigravity's CLI). 401/403 → expired; an expired session keeps its last reading, faded, for 24 h (`checked.json` keeps the last answer across relaunches). 429 → rate limited until Retry-After (clamped to 1 min–6 h) and no call goes out until then, though a cheap local reading (`fetchBetweenCalls`: Claude's status line) still counts. `minimumInterval` spacing counts from the last attempt (`lastAttemptAt`), not the last success, except that a failure for want of a login (signed out: nothing was called) doesn't count, and neither does a check where every call (two or more) failed and none reached a network, as when the Mac wakes before its Wi-Fi: `TokenroomHTTP.networkTally` saw no answer of any status during the check and at least one `URLError` that means no network (not connected, connection lost, can't find or connect to the host, DNS, data not allowed, roaming off). A server's error (5xx, 404, 400) or a timeout reached the provider, keeps its spacing, and isn't retried. Only that offline check is tried once more 45 seconds later (`offlineRetryDelay`), as an ordinary check: each provider's spacing and Retry-After hold and no login is renewed unless it's due; a retry that can't connect either leaves it to the timer, and sleep cancels it; an expired session the server refused keeps the spacing. A sign-in or a key saved or removed (`credentialsChanged`) waits for the check in flight, then clears the spacing and any Retry-After, the client's own included (`ProviderClient.credentialsChanged`: Claude's); times from before the clock was set back don't hold calls off. `notEntitled` (e.g. Grok Bot off-plan) shows the reason without Sign In. Credential reads (files, SQLite, `/usr/bin/security`) run through `BlockingIO`, never on the main thread or the cooperative pool. `BlockingIO.runProcess` keeps output as it is read and closes its end of stdout a second after the process exits, so a child left holding stdout open neither blanks the output nor keeps the reader waiting. Keychain calls and the `security` tool run one at a time (`KeychainGate`): overlapping legacy keychain calls deadlock and pin the menu on Updating. A check still ends at its budget if one of them doesn't return, and a between-calls read has that same budget. The budget's timer waits on the main thread, because a stuck keychain call blocks the dispatch workers `Task.sleep` would use. Every request passes its `Provider` explicitly and carries the `Tokenroom/<version>` User-Agent (Claude's direct read sends the installed CLI's instead). Build requests with `TokenroomHTTP.request` when a client needs the status first (fallbacks, error bodies); tests swap the session with `TokenroomHTTP.overrideSession`. Independent last-good cache in `~/Library/Application Support/Tokenroom/`. Coalesce overlapping refreshes. Persist the snapshot cache once per cycle. Reuse the Cursor token for Grok Bot within 20s. Reuse a non-expired Claude keychain read.

Signed-out cards show a **Sign In** button (**Add Key** for key providers). Settings tabs: General, Providers (Enabled, Detected on this Mac, Available, Organization billing), API Keys (coding plans, official APIs such as Copilot's token, pay as you go, organization billing), Alerts (shared `AlertPreferences`, kept in step with iCloud by `AlertPreferencesSync`: a change made here goes out laid over the newest shared copy, field by field and threshold level by level, and is retried until iCloud has it; a change made in Settings while one syncs stays, on top; iCloud is read at most every 30 minutes while nothing changed here; a change made here is dated but keeps the shared time zone, and quiet hours take this Mac's zone only when it changes, shared without dating it (`AppSettings.followedTimeZone`, checked by `QuotaStore.followTimeZone` before each sync: every refresh and when Settings opens; the first launch only notes it, unless this Mac never shared the choices, so it doesn't undo the iPhone's)), News (opt-in, labs, feeds), Menu Bar, iPhone & Watch. `SettingsTabRequest` picks the tab when something else opens Settings. Settings is one resizable AppKit window (`AppDelegate.openSettings`), with provider and lab/source search and Claude bridge controls under Advanced; the SwiftUI `Settings` scene is empty and ⌘, goes to the AppKit window. Key sheets start from the choice saved with the key (Copilot's plan), and more than two choices show as a menu. Signed builds keep pasted keys in the data-protection keychain (`APIKeyStore`) and copy login-keychain keys there on first read, preserving metadata. Saving updates an existing item in place and adds only when absent, so a failed save keeps the previous key. A legacy delete can remove the protected copy too, and deleting before a durable copy can lose the only key when restoration fails, so migration retains the existing legacy item until an explicit Remove clears both; errors from either deletion are reported. Keychain and settings-file work in Settings runs through `BlockingIO`. Turning a provider off does not log the user out of that provider. Settings turns providers on and off through `QuotaStore.setEnabled`: one turned on is checked at once, within its spacing and Retry-After (the login didn't change), and either way the next iCloud round goes out at once (`RelayPublisher.providersChanged`), as it does when a key's removal turns a provider off. A new Refresh every goes through `setRefreshMinutes` and starts the timer's wait over; a timer check under way finishes. Budgets re-apply to the reading the status holds, whatever the status, and never bring back one the expired session's 24 hours dropped. If a session is already usable, Sign In finishes immediately instead of waiting. A Claude, Grok Build, or Codex login that can still be renewed counts as usable, so Sign In does not start a second login; once that refresh grant is rejected, it does. A Claude Keychain item with an expired refresh token is not usable — Sign In runs `claude auth logout` then `claude auth login`. The CLI is `claude` on PATH, otherwise the newest binary in `~/.local/share/claude/versions` or Claude Desktop’s bundled `claude`. Keychain services `Claude Code-credentials` and `Claude Code-credentials-*` are both read. Network timeouts stay unreachable (last good reading), not expired.

A forced refresh never cancels the check in flight (its calls are already out; calling a rate-limited provider again at once can earn a 429): forced refreshes asked for meanwhile share one follow-up check covering every provider they asked for, with the spacing rules keeping just-checked providers resting. Sending to iCloud (readings, history, alerts, and once a day deleting alert records older than two weeks) and News run after a check, outside it, one round at a time (a check that finishes meanwhile leaves one more round); the timer's checks don't wait for them, so a slow iCloud doesn't hold up the next check, while forced refreshes (the popover button, sign-in, waking) return once readings are shared. Going to sleep cancels the check in flight, the follow-up, and the sharing round; a cancelled pass doesn't count its cut-short checks as failures or attempts, and a cancelled iCloud call isn't reported as an iCloud problem (`RelayErrorPolicy.Outcome.cancelled`); a share asked for while that cancelled round is still ending gets a round of its own (`willSleep`, `share`). Each iCloud call the Mac makes (`RelayPublisher.iCloud`, through `RelayCloud`, which tests stand in for) gives way after 20 seconds, as on the iPhone; a call that doesn't answer is waited out like a dropped connection (retry after the minimum interval), so the rest of the round doesn't wait on iCloud call by call. Turning Send readings to iCloud off while a send is out keeps it Off, and turning it on again always starts afresh: zone re-created, everything sent. Off is checked before every write (each alert of a batch included), so none starts after it; one already out, or one abandoned at the 20 seconds, may still land. `currentTimeZone` resets Foundation's cached zone each time it's read, so quiet hours follow a move on the next sync (`followTimeZone`, never on a choice change), and times shown follow `NSSystemTimeZoneDidChange` without a relaunch. Waking always checks again. A measured run-out goes to iCloud once it moves an hour from the one last sent (`RelayPublishPolicy`), not with every drift. Once a save finds Tokenroom's iCloud data deleted in iCloud settings, the Mac remembers it in its defaults, for that iCloud account (`RelayZoneDeletion`, by a fingerprint of the account; PRIVACY.md says so), and doesn't make that account's zone again, across launches and sign-outs, until sync is turned off and on (`resetZone`) or the zone is back (made again from the iPhone's Delete); another account isn't held back; a Mac that was off when the data was deleted still makes it again on its first save, as it sends before it reads. `usageEqual` takes reset times within a minute as the same. The pace relayed with each window is measured as of the newest reading.

Settings v2: the saved enabled list is authoritative for every provider in `knownProviders` (an empty list stays empty). A provider the settings never saw starts enabled only if `enabledByDefault`, or when a local session is found after launch, off the main thread (`newlyKnown`, `enableDetected`). Organization billing never turns on by itself. `Provider` is a plain `String` enum, not a lenient struct: IDs a newer Tokenroom wrote are skipped when read (the snapshot cache and settings decode entry by entry), and settings save them back untouched (`ForeignChoices`), so going back to the newer version keeps its choices. Readers of the relay use string IDs, so an older iPhone still shows a provider a newer Mac added. Meter fill is clipped to the track capsule; 0% used draws no fill.

## Popover

Cards show the meter with a pace tick (`paceMark`), the pace line for every verdict (tight or critical color only when ahead or out), and a forecast line for balances and org spend. Clicking the header expands a card: reset date, the week's `Sparkline`, every other window as a `WindowRow`, banked resets with expiries, plan, last check, and the unofficial note. More than five connected providers switch to one line each (`isCompact`), expanding on click. The footer strip (`HighlightPill`s) counts banked resets, unseen models, and unseen official releases matching its destination, shortening its labels when all three show; News opens in its own window (`NewsWindowView`, off until turned on): native sidebar Today / Following / Skills / Saved plus retained Models / Announcements / Retiring / Voices / Status collections, then followed labs/tools. Popover requests retain `NewsFilter`, `macNewsSection` and `NewsPageRequest`; selecting a lab/tool or searching never prevents a new request from opening its section; the outer request observer retains a request made while News is disabled. `NewsReaderContent` routes Mac presentation through `MacNewsReaderContent` and the desktop components; iOS retains its own composition. They share attributed metadata and native details with Save/Share/Open Original, collection-scoped source health with shared News progress and paired-feed targeted recovery, read state and local saved metadata. `NewsLibrary` and `SkillsStore` stay at the window boundary. Public voices use opt-in feeds/X profiles; profile-only follows do not fetch. Status is separate and opt in. ClawHub metadata shelves are bounded and ephemeral; no skill downloads or execution, X API or News iCloud sync. Check Now, News Settings and native search remain in the unified toolbar through `sceneBridgingOptions`. Minimum 820 × 560. News debug captures now use the titled `renderWindow` harness; offscreen sidebar selection artifacts still do not establish real keyboard/window acceptance. ## Settings window

Settings is a `NavigationSplitView`: a sidebar with "Search settings" (matches page titles, descriptions, and provider names, and jumps to the first match), sections Essentials (General, Menu Bar), Usage (Providers, API Keys, Alerts), and More (News, iPhone & Watch), each page a System Settings tile (`SettingsIcon`). Each page's form starts with `SettingsHeaderSection` (tile, title, one line, a `SettingsTag` count such as "11 of 16 on"). Provider rows carry tags: Unofficial, Key, Admin key, Login or token, Detected. The window opens at 820 × 620 with a unified toolbar; snapshots render it in a titled window (`renderWindow`).

## Test host

Under XCTest (`LaunchEnvironment.isUnitTestHost`) the app builds an empty store and starts nothing: no status item, no checks, no Keychain, no iCloud. Tests make their own stores with stubbed readers, so `xcodebuild test` never reads or renews this Mac's logins.

## Copy

No apologies. Errors start with “Couldn't…”. Sign-in lines name the real command (`grok login`, `claude login`, `codex login`, “Sign in to Grok Bot”, “Sign in to Cursor”).
